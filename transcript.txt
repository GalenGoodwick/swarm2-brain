The hot weight gates how much each other neuron's vote counts. Warm thread = strong edge = strong mutual evaluation; a neuron "agrees with" the neighbors it's hot-threaded to. CLAUDE:
The honest answer is they're each better at *different* jobs the threads have to do — which is what decides it.

**Consecutive-only** = a pure bigram transition model. `the cat sat` → `the→cat, cat→sat`. Sparse, clean, directional. **Best for the language-model job** (the speaking walk): every edge is a *real* grammatical transition, so the thread-walk decoder can't step to a word that never actually followed.

**Windowed ±2** = adds skip-grams. `the cat sat` also gets `the→sat, cat→…`. Denser. **Best for the identity / evaluation / search jobs**: it captures that non-adjacent words relate ("cat"↔"mat"), which gives centrality and vector search much more signal — especially early, when a conversation is short and consecutive-only is nearly empty.

So there's a genuine tension: **consecutive is better grammar, windowed is better association.** And the threads have to serve both.

The resolution that gets both, and why I lean windowed:

**Windowed ±2, distance-decayed and directed** — adjacent edge weight `1.0`, skip-1 edge weight `0.5` (i.e. `1/(j−i)`). This *subsumes* consecutive-only: the true transitions still dominate by weight, so the speaking-walk favors real adjacency and grammar holds — but you also get the discounted skip layer for free, feeding identity and search. It's strictly more information with no grammar cost, because weight-dominance protects the walk. (It's also exactly how word2vec/GloVe themselves weight context — by `1/distance`. Same principle.)

Consecutive-only is the *degenerate case* of this at `weight=0` for skips — so we lose nothing by defaulting to the window: it's a **one-line knob** (`WINDOW`, `weight=1/dist`), and if the skip edges ever muddy the decode in practice, `WINDOW=1` ablates it back to pure consecutive in a single flag.

**Recommendation: windowed ±2, distance-decayed, directed — with the walk reading the weights so grammar stays adjacency-driven.** Want me to lock that into the spec (§4 step 3 + close the open decision), and is your instinct the same, or are you worried the skip edges will dilute the English?

## Do cells act like attention heads?

**Yes — closer than analogy, with one structural difference.** Line the mechanisms up:

| Transformer | swarm2 tournament |
|---|---|
| attention head: query·key match | evaluator: `dot(evaluator_pos, candidate_pos)` — the evaluator's position **is** a query, candidates are keys |
| multi-head (parallel perspectives) | the 5-evaluator panel — five positioned perspectives scoring in parallel |
| attention mixing across tokens | **Pass 2 deliberation** — each evaluator shifts 20% toward the collective field and re-scores. That's literally one step of message-passing attention |
| soft weighted sum | **hard vote** (argmax winner) |

So: **evaluator ≈ head, cell ≈ a multi-head block, tiers ≈ layers** (winners advance through repeated panels = depth). The m100 finding was exactly this — attention pattern = thread was an isomorphism, not a metaphor — and the cell structure extends it.

The structural difference: attention is **soft** (weighted mixture, differentiable), cells are **hard** (discrete winner). Which leads to your gradient question:

**Do they act like gradients? No — and that's precisely what's missing.** A gradient is an *error-driven* update: backprop punishes the network for being *wrong*. Our updates (Hebbian pull, shift, spring, thread-warming) are *correlation-driven* — "fire together, wire together." Nothing in the system is ever told it was wrong. The evaluator score distribution is a "gradient" in the loose sense (a preference field over candidates), but no error flows backward through it. Correlation learning stores; error learning *improves*. That gap is the answer to your first question.

## What incentive parameters / training would improve intelligence?

In order of leverage — and #1 is the big one:

**1. Prediction-error learning (surprise-weighted threads).** This *is* the LLM training loss, done geometrically: before absorbing each incoming word, have the brain **predict** it (run the word-tournament on the context it already has). If the prediction is right → tiny reinforcement (it already knew). If wrong → strengthen the *actual* transition **proportional to the surprise**, and slightly weaken the path it wrongly predicted. Now input isn't just data to store — it's **supervision**. Redundant input teaches nothing; surprising input teaches a lot. That single change converts the system from a recorder into a *learner*, and it's cheap (the predictor already exists — it's `speak`'s next-word tournament).

**2. Evaluator credit assignment.** Evaluators are currently unweighted judges. Give each a reputation: evaluators whose votes picked candidates that *later recur/survive* gain weight; consistently wrong judges fade. Then **the tournament learns how to judge** — selection pressure on the judges themselves, which is the RL-flavored layer the cradle never had.

**3. Compression-incentivized chunking (MDL).** Crystallize a chunk not when it's merely *hot* but when it **shortens the description** of the stream (fewer, better-predicting units). Chunks that don't improve prediction dissolve. Compression-as-incentive is the cleanest formal proxy for intelligence, and it makes hierarchy *earn* its existence.

**4. Champion accountability.** The champion currently wins on centrality alone. Make it pay rent: if its decompression predicts subsequent input well, its crown strengthens; if not, it decays. That's grounding-lite — the meta precedent held to a predictive standard.

Honest boundary, as always: 1–4 make it a genuinely *learning* system — better prediction, earned hierarchy, self-improving judgment — i.e., LLM-like intelligence by the LLM's own measure (prediction). Reasoning-toward-goals still needs the external grounding loop; no internal incentive substitutes for reality.

**Recommendation: build #1, prediction-error learning.** It's the highest-leverage, it reuses the existing generator as the predictor, and it makes every AI feeding the brain a *teacher* instead of a dictation source. Want it?
